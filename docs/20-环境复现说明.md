## 2. 两个必须单独确认的外部依赖

### 2.1 COMSOL Multiphysics 6.3

pip 装不了，必须本机安装。脚本里全部用 `mph.start()` 连接，MPh 会自动发现本机 COMSOL 安装。

验证方式：

```powershell
myenvs_fipynaca2.0\Scripts\python.exe -c "import mph; c = mph.start(); print(c)"
```

若报找不到 COMSOL，检查 COMSOL 安装路径是否在系统 PATH，或显式指定：

```python
import mph
client = mph.start(cores=1)  # 首次启动较慢，属正常
```

注意：文档中有一处残留的 `Comsol 6.1` 记录，为历史版本，当前以 **6.3** 为准。

### 2.2 GPU（当前不可用）

检测结果：

- `nvidia-smi`：无输出，本机无 NVIDIA GPU 或未装驱动。
- `torch.cuda.is_available()`：`False`
- `torch.version.cuda`：`None`

影响：所有训练脚本都写的是

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
```

**实测全部落在 CPU 分支**。U-Net 训练、K 折验证、消融实验的耗时都是 CPU 基线，论文中若要写训练耗时，须说明是 CPU 环境，不能按 GPU 口径描述。

若后续换到有 GPU 的机器：

```powershell
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

## 3. 从零重建环境

```powershell
cd F:\pyProject\fipy_naca0012_2.0

# 1. 建虚拟环境
python -m venv myenvs_fipynaca2.0

# 2. 装依赖（注意 numpy 为预发布版，需 --pre）
myenvs_fipynaca2.0\Scripts\python.exe -m pip install --upgrade pip
myenvs_fipynaca2.0\Scripts\python.exe -m pip install --pre -r requirements.txt
```

> `numpy==2.4.0rc1` 是预发布版本，不加 `--pre` 会解析失败。若想用稳定版，把 requirements.txt 中该行改为 `numpy>=2.1,<2.4` 后重装，但需回归验证——当前结果都是在该 rc 版下跑出来的。

## 5. 已知环境约束

1. **torch 是 CPU 版**，训练耗时不可按 GPU 口径写入论文。
2. **numpy 为预发布版 2.4.0rc1**，重建需 `--pre`；换稳定版需重跑回归。
3. **FiPy 4.0.1 仍在环境中**，属旧六参数遗留依赖，当前七参数主线不调用，不要因"没用到"而清理。
4. **COMSOL 6.3 为商业许可**，换机需重新授权，这是复现链条上唯一无法自动化的环节。
5. 项目自带 `myenvs_fipynaca2.0/`（约 1.9 万文件），已按 `.gitignore` 规则排除提交，交接时须单独拷贝或按本文重建。
