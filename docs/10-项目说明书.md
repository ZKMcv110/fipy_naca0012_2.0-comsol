## 1. 一句话说明

本项目研究翼型柱阵列散热器的二维流热耦合仿真、代理模型预测、差分进化优化和三维芯片级散热器复核。

当前主线不是旧六参数 CNN，也不是单纯几何掩码模型，而是：

```text
七参数结构参数
    -> 二维 COMSOL / PVT 流热场数据
    -> MLP-CNN / U-Net 流热场重建代理模型
    -> 预测 Nu、f、eta
    -> DE 优化 eta
    -> COMSOL 复算验证
    -> 三维芯片级散热器复核
    -> 论文图表和正文整理
```

主线和旧线关系：

| 名称 | 是否当前论文主线 | 作用 |
|---|---|---|
| 七参数 MLP-CNN / U-Net PVT 流热场重建 | 是 | 当前论文方法主线，突出 CNN 对流场重建和性能预测的作用 |
| 七参数几何掩码代理优化 | 保留但不是唯一主线 | 保留 500 组、1000 组闭环结果，可作为对照和证据来源 |
| 旧六参数 CNN / CBAM / PI-CNN | 否 | 历史流程、旧结果和可追溯材料，不能删 |
| 三维 COMSOL | 是验证环节 | 用二维优化结构做三维迁移复核，不是三维优化器 |

### 4.1 PVT 主线的数据链

PVT 主线的意思是：模型不只预测 `Nu` 和 `f`，还用 CNN / U-Net 重建压力、速度、温度场。

```text
七参数 Ta、Twa、Tb、Ts、Tt、Tad、theta
    -> 参数归一化
    -> MLP 编码
    -> CNN / U-Net 解码
    -> 重建 p、U、T 场
    -> 指标分支预测 Nu、f
    -> 计算 eta
    -> 差分进化 DE 找 eta 最大结构
```

关键数据文件：

| 文件或目录 | 作用 |
|---|---|
| `data/field_reconstruction_dataset_320x96_full_pUt.npz` | PVT 流热场重建数据集，本地大文件，不进普通 Git |
| `results/` | 训练结果、指标、预测图 |
| `analysis_results/` | 敏感性、网格无关性、消融等分析结果 |
| `reports/论文证据链总表.md` | 论文证据链汇总 |
| `reports/最终交付状态报告.md` | 当前实验完成状态 |

### 4.3 论文里怎么描述这条主线

可以这样理解：

1. 七参数决定翼型柱阵列几何。
2. COMSOL 给出对应的压力、速度、温度场和 `Nu`、`f`。
3. MLP 负责把七参数编码成潜在特征。
4. CNN / U-Net 负责把潜在特征解码成流热场图像。
5. 指标分支预测 `Nu`、`f`，再计算综合指标 `eta`。
6. DE 只调用代理模型，不直接调用 COMSOL。
7. 最优结构最后再回到 COMSOL 复算验证。

9. GitHub 上没有保存所有大文件，本地目录才是完整工程。
10. `完整论文初稿_图片汇总_svg/` 只是可编辑图备份，不代表论文已经改用 SVG。

## 14. 常见问题

### 14.1 为什么 Markdown 看不到图

常见原因：

1. Markdown 里还是旧路径。
2. 图片在 `完整论文初稿_图片汇总/`，但正文指向 `figures/`。
3. 文件名有中文、空格或括号差异。
4. 图片后缀从 `.png` 变成 `.svg`，正文没同步。

处理顺序：

```text
先查 Markdown 图片路径 -> 再查图片是否存在 -> 再决定是否修改正文路径
```

### 14.2 为什么 GitHub 看不到某些模型

因为 `.mph`、`.pt`、`.npz` 等大文件已被 `.gitignore` 忽略。它们仍在本地，但不进普通 GitHub。

### 14.3 为什么三维图看着效果不明显

三维和二维的边界条件、热源形式、流动空间、指标定义都不同。二维 `eta` 高，不代表三维一定大幅提升。论文里要把三维写成“迁移验证”，不要写成“直接证明最优”。

### 14.4 为什么几何掩码和 PVT 主线都存在

这是项目演进结果：

1. 几何掩码旧主线用于七参数结构到 `Nu/f/eta` 的代理预测。
2. PVT 主线用于七参数到压力、速度、温度场的重建，更能体现 CNN。
3. 当前论文更适合把 PVT 流热场重建作为主线。

### 14.5 为什么 PNG 转 SVG 后不是完全一样

PNG 是栅格图，不能无损变成原生矢量图。当前脚本用 `vtracer` 做近似矢量化，所以能编辑路径，但细节和原图不会完全一样。
