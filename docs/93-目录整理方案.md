# 项目目录整理方案

本文档用于整理当前 `fipy_naca0012_2.0` 工作区。原则是：不破坏现有脚本硬编码路径，不移动当前七参数主线证据链；旧六参数、旧答辩、临时实验和缓存按风险分层归档。

## 1. 当前结论

当前项目可以整理，但不能直接大规模移动目录。原因是很多脚本和论文证据链已经硬编码以下路径：

- `七参数_MLP_CNN流场重建/`
- `七参数_几何掩码代理优化/`
- `七参数_PDE_PINN尝试/`
- `comsol_3d_airfoil_radiator/`
- `大论文初稿/`
- `consol_cfddata/`
- `模型脚本/`
- `工具脚本/`

因此第一阶段只做安全整理：新增目录说明、归档清单、删除明显缓存；第二阶段再按清单移动旧材料。

这些目录或文件是当前主线、证据链或运行入口，暂时不要移动：

## 4. 可以清理的缓存和临时文件

这些内容通常可以删除，但删除前仍建议先确认没有正在运行的进程占用。

| 路径 | 处理建议 |
|---|---|
| `.pytest_cache/` | 可删除 |
| `.tmp_pytest/` | 可删除，当前存在权限提示，需关闭相关进程后再删 |
| `__pycache__/` | 可删除 |
| `pde_extract_err.txt` | 空文件，可删除 |
| `pde_extract_log.txt` | 临时日志，可归档或删除 |

- `.env`

- `myenvs_fipynaca2.0/`

## 7. 安全执行顺序

### 第一阶段：不破坏路径的清理

1. 保留当前主线目录不动。
2. 删除或归档缓存：`.pytest_cache/`、`__pycache__/`、空日志。
3. 更新 `项目目录说明.md`，明确当前论文主线是 `七参数_MLP_CNN流场重建/`。
4. 在 `归档/` 下建立分类目录，但暂不移动有硬编码依赖的旧数据。

### 第二阶段：移动低风险历史材料

1. 移动 `outputs/` 和 `projects/` 到 `归档/历史答辩材料/`。
2. 移动 `academic_pre_review_committee_loaded*`、`thesis_writing/` 到 `归档/旧论文材料/`。
3. 移动小论文旧图到 `归档/旧论文图件/`。
4. 移动 `mcp_comsol_demo/`、`tmp_mesh_export_test/` 到 `归档/工具示例/`。

### 第三阶段：处理旧六参数流程

1. 先不要移动 `consol_cfddata/`，因为旧脚本硬编码很多。
2. 若确实要移动，先批量修改旧脚本路径并跑最小验证。
3. 旧模型结果目录可以归档，但要保留 `README` 指向新位置。

## 8. 当前不建议做的事

- 不建议删除 `consol_cfddata/`，它是旧 500 组 CFD 原始结果，重建成本高。
- 不建议移动 `七参数_MLP_CNN流场重建/`，当前论文证据链依赖它。
- 不建议移动 `七参数_几何掩码代理优化/`，二维 COMSOL 单工况和历史结果还在被引用。
- 不建议移动 `comsol_3d_airfoil_radiator/`，三维迁移验证和网格补算都依赖它。
- 不建议把旧六参数结果写进当前七参数论文结论。
